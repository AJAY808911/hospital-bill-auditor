## 1. Problem Statement & Project Objective
In India and global healthcare systems, hospitalized patients frequently face unexpected out-of-pocket medical expenses. When filing cashless or reimbursement health insurance claims, insurers routinely apply substantial deductions for:
1. **Daily Room-Rent Limits & ICU Caps**
2. **Proportionate Deductions** on associate medical services (doctor consultations, OT charges, surgeon fees)
3. **Non-Payable Consumables & Admin Fees** (IRDAI non-payable list items like gloves, masks, PPE, syringes, registration charges)
4. **Mandatory Deductibles and Co-Payments**

**Hospital Bill Auditor** is an end-to-end, deterministic web application designed for a Computer Science Final Year / College Project. It allows patients and healthcare billing staff to upload or manually enter hospital bills, configure policy terms, detect non-payable items, apply strict insurance financial rules, trace every deduction to specific policy clauses, and preview the estimated payable settlement before submitting claims.

> **Statutory Disclaimer**: All outputs generated by this system are pre-claim estimations for educational and informational purposes. They do not constitute legal advice or official insurer claim approval guarantees.

## 2. Technology Stack & Architectural Decisions

| Layer | Selected Technology | Why Selected |
| :--- | :--- | :--- |
| **Frontend** | React 18, TypeScript, Vite, Tailwind CSS, Lucide Icons | High-performance, type-safe Single Page Application with clean medical fintech aesthetics and sub-second compilation. |
| **Backend API** | Python 3.13, FastAPI, Uvicorn | High-throughput asynchronous REST framework with native Pydantic v2 schemas and automatic interactive Swagger UI at `/docs`. |
| **Financial Engine** | Python `Decimal` (`ROUND_HALF_UP`) | Zero floating-point rounding errors (eliminates IEEE-754 binary representation discrepancies). Exact, explainable, and reproducible financial math. |
| **Database** | SQLite + SQLAlchemy 2.0 ORM | Embedded, zero-configuration relational database with foreign key relationships (`audits` 1-to-many `audit_items`), suitable for local college defense. |
| **PDF Extraction** | PyMuPDF (`pymupdf` / `fitz`) | Fast local extraction (<50ms) of text blocks, tables, and numeric items without external cloud API dependencies. |
| **Local OCR** | `pytesseract` + Pillow (Tesseract OCR) | Local fallback for scanned bills with optical noise detection and review warnings. Gracefully falls back to manual entry if Tesseract is not installed. |
| **Report Generation** | ReportLab | Server-side vector PDF generation for official, downloadable audit summary sheets. |
| **Optional AI** | Decoupled Provider (`GEMINI_API_KEY` or `OPENAI_API_KEY`) | Strictly optional helper for text categorization and narrative summaries. Financial calculations are **100% deterministic** and NEVER rely on AI. |

## 4. Key Features

- **Multi-Source Bill Processing**:
  - Digital PDF bills: Automatic parsing of table lines, rates, quantities, and totals.
  - Scanned image bills: Local OCR processing with confidence reporting and graceful fallbacks.
  - Manual Entry: Add, edit, or delete line items with strict input validation preventing negative or invalid numbers.
  - Editable Normalization Table: Interactive categorization dropdowns with color-coded badges.
- **Configurable Insurance Policies**:
  - Sum Insured limits.
  - Room-rent limits (Fixed daily amount, % of Sum Insured, or No Limit).
  - Proportionate deduction toggles and custom ratio overrides.
  - Co-payment percentages (0% to 100%) and mandatory deductibles.
  - Non-payable schedules (IRDAI consumables & admin charges).
- **Independent Deterministic Rule Engine**:
  - Independent of external AI APIs.
  - Exact Python `Decimal` financial arithmetic.
  - Strict reconciliation verification (`billed == payable + shortfall`).
- **Downloadable PDF Audit Reports**:
  - Official multi-page vector PDF summaries generated via ReportLab.
- **Persistent Audit History**:
  - Relational SQLite storage with full CRUD capabilities.
- **College Viva Demonstration Case**:
  - 1-click execution of the mandatory ₹1,50,000 demonstration case producing ₹1,08,000 payable and ₹42,000 shortfall.
- **Viva Defense Guide**:
  - In-app technical Q&A covering algorithms, IEEE-754 floating-point vs. Decimal, and IRDAI rules.

## 6. Installation & Setup

### Clone the repository
```bash
git clone <repository_url>
cd hospitalbileditior
```

### Backend Setup
1. Create and activate a Python virtual environment (optional but recommended):
```bash
python -m venv venv
# On Windows:
venv\Scripts\activate
# On Linux/macOS:
source venv/bin/activate
```
2. Install Python dependencies:
```bash
python -m pip install -r backend/requirements.txt
```

### Frontend Setup
1. Navigate to the frontend directory and install dependencies:
```bash
cd frontend
npm.cmd install
cd ..
```
2. Build the production frontend assets:
```bash
cd frontend
npm.cmd run build
cd ..
```

## 9. Section 7 Required Demonstration Case Walkthrough

To verify the mandatory viva test case:
1. Open the application at [http://127.0.0.1:8000](http://127.0.0.1:8000).
2. Click **"Run Viva Demo"** in the top navigation bar or navigate to the **"Section 7 Demo"** tab.
3. Review the exact inputs and verified calculations:

### Inputs:
- **Total Hospital Bill**: ₹1,50,000
  - Room Rent (Deluxe Ward - 5 Days @ ₹5,000/day): ₹25,000
  - Doctor, Nursing, and OT charges: ₹60,000
  - Pharmacy & medications: ₹30,000
  - Gloves, masks, and administrative fees: ₹8,000
  - Diagnostics & lab investigations: ₹27,000

### Policy Rules Applied:
- Room-rent limit: ₹3,000 per day.
- Length of stay: 5 days.
- Allowed room rent: 5 × ₹3,000 = ₹15,000 (Deduction: ₹10,000).
- Proportionate deduction ratio: `₹3,000 / ₹5,000 = 0.60 (60%)`.
- Doctor & OT charges allowed: `₹60,000 × 0.60 = ₹36,000` (Deduction: ₹24,000).
- Pharmacy: Fully payable = ₹30,000.
- Diagnostics: Fully payable = ₹27,000.
- Consumables & Admin fees: Non-payable = ₹0 (Deduction: ₹8,000).

### Results:
| Particulars | Billed (₹) | Estimated Payable (₹) | Shortfall / Deduction (₹) | Audit Reason |
| :--- | :---: | :---: | :---: | :--- |
| Room Rent | 25,000.00 | **15,000.00** | 10,000.00 | Capped at ₹3,000/day × 5 days |
| Doctor, Nursing & OT | 60,000.00 | **36,000.00** | 24,000.00 | Proportionate deduction (60% allowed) |
| Pharmacy | 30,000.00 | **30,000.00** | 0.00 | Eligible in-patient medicine |
| Gloves, Masks & Admin | 8,000.00 | **0.00** | 8,000.00 | IRDAI Non-Payable Consumables Schedule |
| Diagnostics | 27,000.00 | **27,000.00** | 0.00 | Eligible diagnostic investigations |
| **TOTALS** | **1,50,000.00** | **1,08,000.00** | **42,000.00** | **Reconciliation Verified (100%)** |

4. Click **"Download PDF Report"** to inspect the ReportLab-generated official PDF summary.

## 10. Environment Variables & Configuration

The application is fully functional out-of-the-box with default zero-configuration SQLite.
To customize settings or enable optional external AI, create a `.env` file in the root directory:

```env
# Database file location
DATABASE_FILE=hospital_auditor.db

# Optional AI API Keys (Never committed to Git)
# When provided, AI assists in suggesting categories for ambiguous descriptions.
# If omitted, local deterministic regex and keyword heuristics run automatically.
GEMINI_API_KEY=your_gemini_api_key_here
# OR
OPENAI_API_KEY=your_openai_api_key_here
```

## 11. Known Limitations & Future Enhancements

### Limitations
1. **Scanned PDF OCR Dependency**: Processing scanned image PDFs without an embedded text layer requires Tesseract OCR installed on the host OS. When not installed, the application alerts the user and provides an immediate manual entry fallback.
2. **Standardized IRDAI List**: While over 200 common medical terms are heuristic-matched, rare proprietary hospital line-item acronyms may initially fall into `AMBIGUOUS_UNCATEGORIZED` and require user confirmation.

### Future Enhancements
- Integration of Ayushman Bharat Digital Mission (ABDM) FHIR billing standards.
- Cashless hospital network claim pre-authorization integration.
- Multi-currency support for medical tourism bills.
